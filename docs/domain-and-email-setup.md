# Booking domain and email setup

Production origin: `https://book.nzesports.org.nz` (no trailing slash).

The shared `lib/site-url.ts` supplies authentication, notification, feedback, calendar-download, payment, and template-preview links. Production defaults to the booking domain; an explicit `NEXT_PUBLIC_SITE_URL` overrides it. Local development stays on localhost. Vercel previews use their deployment URL when no explicit URL is configured.

## Vercel

In the **booking project's Settings → Domains**, add `book.nzesports.org.nz`, assign it to Production, and complete the DNS records Vercel displays. Confirm the domain has valid DNS and HTTPS. Configure old booking domains to redirect to it, preserving paths and query strings. Do not redirect the separate NZ Esports corporate website.

In **Settings → Environment Variables**, select **Production**:

| Variable | Value |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `https://book.nzesports.org.nz` |
| `BREVO_API_KEY` | Your Brevo transactional API key (secret) |
| `BREVO_SENDER_EMAIL` | An actual verified sender address; current default is `info@esf.nz` |
| `BREVO_SENDER_NAME` | `NZ Esports` |
| `BREVO_CONTACT_EMAIL` | Inbox for contact-form messages; current default is `schools@esf.nz` |
| `NEXT_PUBLIC_SUPABASE_URL` | Existing production Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Existing production publishable key |
| `SUPABASE_SERVICE_ROLE_KEY` | Existing production service-role key (secret) |

Deploy the updated code after changing variables. Existing deployments do not pick up new values. Leave Development pointing at localhost; configure Preview separately if used.

Sources: [Vercel domains](https://vercel.com/docs/domains/working-with-domains/add-a-domain), [environment variables](https://vercel.com/docs/environment-variables).

## Supabase

In the production project's **Authentication → URL Configuration**:

- Set **Site URL** to `https://book.nzesports.org.nz`.
- Add these **Redirect URLs**, matching the callbacks generated by this application:

```text
https://book.nzesports.org.nz/auth/confirm?next=%2Fschool
https://book.nzesports.org.nz/auth/confirm?next=%2Flogin%3Fverified%3Dambassador
https://book.nzesports.org.nz/auth/confirm?next=%2Freset-password
```

Keep local callback permissions only where local development against that project is intended. `supabase/config.toml` configures the local stack; it does not change the hosted project's settings.

In **Authentication → Email Templates**, remove hardcoded old booking domains. Keep the default `{{ .ConfirmationURL }}` for authentication buttons if using default templates. Custom token-hash templates must preserve `/auth/confirm`, the token hash, the appropriate auth type, and the intended `next` destination; replacing a verification button with a plain homepage link will break authentication.

In **Authentication → Email / SMTP Settings**, configure custom SMTP for signup, password-reset, and invitation emails. Use the SMTP credentials from Brevo's SMTP settings and a verified sender. The SMTP password is separate from the `BREVO_API_KEY` used by the application. Supabase's default mail service is restricted and is not suitable for public production signups.

Keep the existing Supabase project URL, API keys, and storage URLs: they identify the backend, not the website domain. If an external OAuth provider is later enabled, its Supabase callback remains on the Supabase project domain.

Sources: [Supabase redirects](https://supabase.com/docs/guides/auth/redirect-urls), [custom SMTP](https://supabase.com/docs/guides/auth/auth-smtp).

## Brevo and saved booking templates

Booking notifications are sent directly through Brevo's HTTP API, not Supabase Auth SMTP. Website URLs and From addresses are separate settings. `https://book.nzesports.org.nz` cannot be a From address. To send from a new mailbox on `book.nzesports.org.nz`, first create/verify that sender and authenticate that subdomain in Brevo using its supplied DNS records, then change `BREVO_SENDER_EMAIL` (and the Supabase SMTP sender if desired). Until then, retain the existing verified sender.

Review **Admin → Email templates** (Supabase table `email_templates`) for hardcoded old links. Use `{{siteUrl}}` for the booking origin, and the template's existing `{{loginUrl}}`, `{{reviewUrl}}`, `{{portalUrl}}`, `{{calendarLinks}}`, or `{{confirmationButton}}` where applicable. The renderer supplies the current domain at send time. Existing database content is not rewritten by deploying code. Do not rerun the template seed script over customized templates just to change the domain.

Source: [Brevo domain authentication](https://help.brevo.com/hc/en-us/articles/12163873383186-Authenticate-your-domain-with-Brevo-Brevo-code-DKIM-DMARC).

## Diagnose a missing booking email

Find the booking in `booking_requests`, then inspect `email_logs` for its ID:

```sql
select created_at, template_key, status, error_message, brevo_message_id
from public.email_logs
where related_booking_request_id = 'REPLACE_WITH_BOOKING_UUID'::uuid
order by created_at desc;
```

- `skipped_unconfigured`: the deployed application lacks `BREVO_API_KEY`.
- `failed`: inspect `error_message` and Brevo's transactional logs for rejected sender, credentials, blocked recipient, or provider/network failure.
- `sent`: Brevo accepted the API request; this is not proof of inbox delivery. Check Brevo's delivery/bounce/block events and the recipient's spam folder.
- No row: confirm the booking exists, then check Vercel Runtime Logs for `[email]` messages. The previous detached-promise implementation could stop before sending or writing logs.

Notifications now register the complete template/send/log operation with Next.js `after()` so redirects do not end their lifetime prematurely. This is bounded by the Vercel function timeout; it is not a persistent retry queue. Network requests time out after 15 seconds and record an unconfirmed delivery failure. Check Brevo before retrying to avoid duplicate emails.

After deployment, manually create a booking and check its receipt and links, then verify signup and password-reset emails separately. Old emails already delivered cannot be rewritten.

Source: [Brevo transactional logs](https://help.brevo.com/hc/en-us/articles/360021533839-Manage-your-transactional-logs-and-email-previews).
